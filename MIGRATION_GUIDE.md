# Migration Guide: Dynamic SSH Key Generation

## Overview

This guide explains the migration from manually managed SSH keys to **dynamically generated SSH keys** using Terraform, eliminating the need for pre-configured Jenkins credentials.

---

## 🔄 What Changed?

### Before (Old Approach)

❌ **Manual SSH key management**
- SSH key had to be created manually in AWS
- Private key stored as Jenkins credential
- Required manual configuration before pipeline runs
- Key management across multiple environments was complex

### After (New Approach)

✅ **Automatic SSH key generation**
- SSH key pair generated dynamically by Terraform
- Private key stored locally in `terraform/kafka-ec2-private-key.pem`
- No manual Jenkins credential configuration needed
- Docker and Kafka installed via SSH (not userdata) for better visibility
- Each deployment gets a unique SSH key

---

## 🎯 Key Improvements

| Aspect | Old Approach | New Approach |
|--------|-------------|-------------|
| **SSH Key** | Manual creation + Jenkins credential | Auto-generated by Terraform |
| **Security** | Shared key across deployments | Unique key per deployment |
| **Setup Time** | 15-20 minutes (manual) | 0 minutes (automated) |
| **Docker Install** | Userdata (hidden logs) | SSH commands (visible logs) |
| **Kafka Install** | Userdata (hidden logs) | SSH commands (visible logs) |
| **Debugging** | Difficult (userdata logs) | Easy (Jenkins console) |
| **Jenkins Credentials** | Required (`kafka-ec2-key`) | Only AWS credentials needed |

## 🚀 Migration Steps

### Step 1: Backup Current Configuration

```bash
# Backup existing Jenkinsfile
cp Jenkinsfile Jenkinsfile.backup

# Backup terraform directory
cp -r terraform terraform.backup
```

### Step 2: Update Terraform Configuration

The following files have been updated:

```bash
# Verify new files exist
ls -l terraform/ssh-key.tf
ls -l install-docker.sh
ls -l setup-kafka.sh
ls -l Jenkinsfile.new
```

### Step 3: Update Jenkinsfile

```bash
# Replace old Jenkinsfile with new one
mv Jenkinsfile Jenkinsfile.old
mv Jenkinsfile.new Jenkinsfile
```

### Step 4: Update terraform.tfvars

Remove or comment out the `key_name` variable:

```hcl
# terraform/terraform.tfvars

# Network Configuration
vpc_id            = "vpc-xxxxx"        # Your VPC ID
subnet_id         = "subnet-xxxxx"     # Your Subnet ID
private_vpc_cidr  = "10.0.0.0/16"     # Your VPC CIDR

# Security Configuration
admin_ip_address  = "YOUR.PUBLIC.IP"   # Your public IP
# key_name = "kafka-ec2-key"          # ❌ REMOVE THIS LINE (no longer needed)

# Optional: EKS Security Group
eks_worker_security_group_id = ""      # Leave empty if no EKS

# Kafka Configuration
kafka_cluster_name = "kafka-cluster-dev"
kafka_broker_id    = 1
```

### Step 5: Remove Old Jenkins Credential (Optional)

Since the SSH key is now generated dynamically, you can optionally remove the old Jenkins credential:

1. Navigate to: **Manage Jenkins** → **Manage Credentials**
2. Find credential ID: `kafka-ec2-key`
3. Delete it (optional - doesn't affect new pipeline)

**Note**: You still need the `jenkins-user` AWS credential!

### Step 6: Run the New Pipeline

1. Commit changes to Git repository
2. Push to remote
3. Run Jenkins pipeline
4. Monitor the new stages:
   - ✅ Dynamic SSH key generation
   - ✅ Docker installation via SSH
   - ✅ Kafka setup via SSH

## 🔑 How SSH Key Generation Works

### 1. Terraform Generates Key Pair

```hcl
# terraform/ssh-key.tf
resource "tls_private_key" "kafka_ssh_key" {
  algorithm = "RSA"
  rsa_bits  = 4096
}

resource "aws_key_pair" "kafka_key_pair" {
  key_name   = "kafka-ec2-key-{timestamp}"
  public_key = tls_private_key.kafka_ssh_key.public_key_openssh
}
```

### 2. Private Key Saved Locally

```hcl
resource "local_file" "private_key" {
  content         = tls_private_key.kafka_ssh_key.private_key_pem
  filename        = "${path.module}/kafka-ec2-private-key.pem"
  file_permission = "0400"
}
```

### 3. EC2 Instance Uses Dynamic Key

```hcl
resource "aws_instance" "kafka_ec2" {
  key_name = aws_key_pair.kafka_key_pair.key_name  # Dynamic reference
  # ... other configuration
}
```

### 4. Jenkins Uses Generated Key

```groovy
sh """
    ssh -i kafka-ec2-private-key.pem \
        ec2-user@${env.EC2_PUBLIC_IP} \
        'command here'
"""
```

## 📊 SSH vs Userdata Comparison

### Old Approach (Userdata)

```bash

# No real-time visibility
# Hard to debug failures
```

**Userdata Execution**:
```
EC2 Starts → Userdata Runs → Jenkins Waits → SSH Access
         (Hidden)           (Blind wait)
```

### New Approach (SSH Commands)

```bash
# Runs via SSH from Jenkins
# Logs visible in Jenkins console
# Real-time output
# Easy to debug
```

**SSH Execution**:
```
EC2 Starts → Jenkins Connects → Installs Docker → Sets up Kafka
         (Visible)          (Real-time)      (Controllable)
```

## 🧰 Testing the Migration

### 1. Test SSH Key Generation

```bash
cd terraform
terraform init
terraform plan

# Check if SSH key will be created
# Look for:
#   + tls_private_key.kafka_ssh_key
#   + aws_key_pair.kafka_key_pair
#   + local_file.private_key
```

### 2. Apply and Verify

```bash
terraform apply

# Verify key file was created
ls -l kafka-ec2-private-key.pem
# Should show: -r--------  (permissions 400)

# Test SSH connection
EC2_IP=$(terraform output -raw ec2_public_ip)
ssh -i kafka-ec2-private-key.pem ec2-user@$EC2_IP
```

### 3. Run Installation Scripts Manually

```bash
# Copy installation script
scp -i kafka-ec2-private-key.pem \
    ../install-docker.sh \
    ec2-user@$EC2_IP:/home/ec2-user/

# Execute
ssh -i kafka-ec2-private-key.pem \
    ec2-user@$EC2_IP \
    'chmod +x install-docker.sh && ./install-docker.sh'

# Verify Docker
ssh -i kafka-ec2-private-key.pem \
    ec2-user@$EC2_IP \
    'sudo docker --version'
```

## ⚠️ Important Notes

### Security Considerations

✅ **Advantages**:
- Unique key per deployment
- Key rotation per environment
- No manual key distribution
- Automatic cleanup on `terraform destroy`

⚠️ **Considerations**:
- Private key stored in Git workspace (add to .gitignore)
- Key destroyed when Terraform state is destroyed
- Backup key if needed for long-term access

### Gitignore Configuration

Add to `.gitignore`:

```gitignore
# SSH Keys
*.pem
terraform/kafka-ec2-private-key.pem

# Terraform
terraform/.terraform/
terraform/*.tfstate
terraform/*.tfstate.backup
terraform/tfplan
terraform/terraform.tfvars
```

### Backup Strategy

If you need long-term access to the EC2 instance:

```bash
# Backup the private key
cp terraform/kafka-ec2-private-key.pem ~/secure-location/
chmod 400 ~/secure-location/kafka-ec2-private-key.pem
```

## 🛠️ Troubleshooting

### Issue 1: "Permission denied (publickey)"

**Cause**: SSH key permissions incorrect

**Solution**:
```bash
chmod 400 terraform/kafka-ec2-private-key.pem
```

### Issue 2: "No such file or directory: kafka-ec2-private-key.pem"

**Cause**: Terraform didn't create the key file

**Solution**:
```bash
cd terraform
terraform output -raw ssh_private_key > kafka-ec2-private-key.pem
chmod 400 kafka-ec2-private-key.pem
```

### Issue 3: "Connection timed out"

**Cause**: Security group doesn't allow SSH or EC2 not ready

**Solution**:
```bash
# Check security group
aws ec2 describe-security-groups \
  --group-ids $(terraform output -raw security_group_id)

# Wait longer for EC2 initialization
# Pipeline has 2-minute wait time
```

### Issue 4: Docker installation fails

**Cause**: Script not executable or network issues

**Solution**:
```bash
# SSH to EC2 and run manually
ssh -i terraform/kafka-ec2-private-key.pem ec2-user@<EC2_IP>
sudo yum install -y docker
sudo systemctl start docker
```
